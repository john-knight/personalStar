一、项目概述
1.1 一句话定位
「双人星球」是一个只属于情侣两个人的微信小程序：一起种菜、互相偷菜、答题比默契、玩双人小游戏，把恋爱变成一场可以每天打开的“双人养成游戏”。
1.2 产品形态
微信原生小程序 + 微信云开发，无需下载 App，扫码即玩。一个微信身份（真人）下可挂多个“情侣空间 / CP 身份”，但系统限制同时只有一对为“活跃关系”，并具备海王识别与防刷榜机制。
1.3 三个核心动词
种：你俩共有一块星球土地，种草莓、月亮花、猫草、纪念树，作物按真实时间生长。
偷：对象可以来“偷”你的作物（10%~30%），刺激每日互动；可买看门猫、篱笆、闹钟防偷。
比：答题测默契、比星球富裕度、比偷菜战绩、比专一度，制造“甜味攀比”。
1.4 目标用户
恋爱中或新婚的情侣，重点是异地恋、年轻情侣（18–30 岁）与喜欢仪式感、爱分享的甜系用户。异地恋用户“不能见面但能一起玩”，是本产品的刚需场景。
二、市场与机会
2.1 为什么是现在
微信小程序具备免下载、社交链天然传播的优势；情侣类产品分享率高（“我们默契 92 分，你们敢测吗”），社交裂变可以摊薄获客成本。市面上的情侣工具多为单一功能（记账、打卡、聊天），缺少“游戏化 + 养成 + 攀比”一体化的产品。

3.2 种菜偷菜（日常留存）
你俩共有一块星球土地，种草莓、月亮花、猫草、纪念树；作物按真实时间生长（如草莓 6 小时成熟）；对象可偷 10%~30%，刺激互动；防偷道具用爱心币或会员解锁。作物不只是装饰：草莓换情话次数、猫草抽扭蛋、纪念树随恋爱天数升级。
3.3 默契问答（攀比裂变）
两人分别答同一套题（如“TA 最爱的奶茶口味”“吵架后谁先低头”），答案一致得分，生成五维雷达图（沟通 / 仪式感 / 情绪 / 未来 / 吃货），并出结果“你们默契 92 分，超过 87% 的情侣”，生成可分享的“情侣报告卡”用于拉新。
3.4 小游戏集合
先上五子棋 / 你画我猜（双人联机），后加拼图（用你们合照）、反应点爱心、故事接龙。所有游戏产出“爱心币”，回星球种地、买皮肤。

四、技术方案
4.1 技术栈
微信原生小程序 + 微信云开发。前端 WXML / WXSS / JS；后端云函数（Node.js）；数据库云开发文档库；登录走 wx.login → openid；实时先用云数据库 watch / 轮询，不急于上 WebSocket。
4.2 架构一句话
微信登录 → openid 识别真人；Couple 关系 → 一对情侣 = 一个星球；云开发数据库 → 作物 / 偷菜 / 答题 / 排行榜；云函数 → 收获 / 偷菜 / 房间同步 / 事务校验；前端 → WXML + Canvas 种菜动画。

4.4 关键实现要点
种菜：存 plantedAt，用 Date.now() − plantedAt 算成熟，不靠前端定时器。
偷菜：云函数校验归属、成熟状态、偷取上限后写回，处理并发与防刷。
多 CP：微信身份 ≠ 情侣关系，一个真人可挂多个 CP，但活跃关系唯一。
可信分：综合实名绑定、双方不同微信、关系存续、设备 / IP 不重合，低于阈值不进正式榜。

八、风险与合规
8.1 主要风险
并发与防刷：两人同时偷同一棵菜、本地改时间骗成熟、开小号自偷，需在云函数内做事务校验与风控。
审核与合规：虚拟会员 / 道具须走微信虚拟支付，不能普通支付或引导私下转账；iOS 上卖虚拟商品须合规。
广告体验：广告不宜过频，避免开局即弹、每局弹多次导致用户流失。
隐私：昵称脱敏、不公开头像真名，提供“不上榜”开关，openid 不放前端。
8.2 合规要点
虚拟权益走微信虚拟支付，实物 / 线下服务走普通微信支付，两者分开。
不做“查某人是不是海王”公开挂人，不接查好友情史类功能。
避免赌博扭蛋、涉黄真心话等违规内容。
